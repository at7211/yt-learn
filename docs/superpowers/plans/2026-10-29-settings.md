# 設定頁：讓使用者決定產課的速度與 effort

## Context

使用者問「可不可以有個 settings 頁面決定翻譯要花多少 effort」。目前模型固定 `claude-sonnet-5-5`（`pipeline/build.py` DEFAULT_MODEL），effort 沒有傳（CLI 預設），切句併行數剛加了 `YTLEARN_WORKERS`（預設 4）。這三個旋鈕都只能用環境變數或指令列調，首頁沒有任何設定。

已查證：`claude -p` 支援 `--model <alias|full name>`（sonnet／haiku／opus／fable）與 `--effort <low|medium|high|xhigh|max>`。產課是 server 的 `BuildQueue._run` 用子程序跑 `python3 -m pipeline.build <vid>`，env 由 `_run` 組（`pipeline/jobs.py:270-276`），所以設定只要在開子程序時放進 env 就能生效，不用重啟 server。

## 設計

**資料**：`data/settings.json`（gitignore 不用改，data/ 其他子目錄已忽略？→ 實作時確認；若沒有就加 `data/settings.json`）。內容：

```json
{"model": "claude-sonnet-5-5", "effort": "default", "workers": 4}
```

- `model`：`claude-haiku-5-5`｜`claude-sonnet-5-5`｜`claude-opus-5-5`（白名單；server 拒絕其他值）。
- `effort`：`default`（不傳 `--effort`）｜`low`｜`medium`｜`high`｜`xhigh`｜`max`。
- `workers`：整數 1–8。

**三個預設組合**（UI 一鍵套用，套用後三個欄位仍可個別改）：
- 快：haiku、low、8 → 「最快最省，中譯與單字品質略降」
- 標準：sonnet、default、4 → 「目前的預設」
- 細緻：opus、high、4 → 「慢兩到三倍、貴兩倍，翻譯與挑字最好」

**server（`server.py`）**：
- `GET /settings` → 目前設定（檔案不存在時回預設值）。
- `POST /settings` body 同上 → 驗證白名單與範圍，原子寫檔（tmp + `os.replace`），回存後的設定；錯誤 400 `{ok:false, errors:[…]}`。CORS 沿用現有規則。
- `BuildQueue._run` 開子程序前讀 `data/settings.json`，塞 env：`YTLEARN_MODEL`、`YTLEARN_EFFORT`（`default` 時不設）、`YTLEARN_WORKERS`。`BuildQueue` 需要知道 settings 檔路徑（建構時由 root 推）。

**pipeline**：
- `pipeline/build.py`：`--model` 預設改為 `os.environ.get("YTLEARN_MODEL") or None`；新增 `--effort`（choices 同上，預設 `os.environ.get("YTLEARN_EFFORT")`），傳給 provider factory；`_default_provider(model, cache_dir, provider, effort=None)`。lesson JSON 的 `model` 欄位改成 `"<model>"` 不變，另加 `"effort": "<effort>"`（`validate_lesson` 若不允許多餘欄位就一併放行這個 key）。
- `pipeline/llm.py`：`_CliProvider.__init__(..., effort=None)`；`ClaudeCliProvider.complete_json` 的 argv 在 `--model` 之後加 `--effort <x>`（有設時）。快取記錄多存 `effort`，讀取時 `model` 與 `effort` 都要相同才命中（effort 改了就重算，這是刻意的）。Codex provider：effort 以 `-c model_reasoning_effort="<low|medium|high>"` 傳（xhigh／max 對應 high；實作前用 `codex exec --help` 與 config 文件確認 key 名，不確定就只支援 Claude 並在 UI 註明）。

**web（首頁）**：
- `web/index.html` 的 `#home` 在課程列表上方或下方加一個 `<details class="settings" id="settings">`，summary 顯示目前摘要（例：「設定：標準・sonnet・4 併行」），展開後：三個預設按鈕（快／標準／細緻）、模型 select、effort select、併行數 number（1–8）、一行說明每個選項對速度與費用的影響（引用 README 費用那節的數字：標準約每分鐘影片 1–2 美分）、「儲存」按鈕與儲存結果文字。沿用 tasteskill 的真黑扁平樣式（`web/style.css` 現有的 `.sheet`、`.fallback` 類別風格），不另加顏色。
- `web/settings.js`（純 ES module，可被 node --test 測）：`PRESETS`、`normalize(obj) → {settings, errors}`、`summary(settings) → string`、`presetOf(settings) → 'fast'|'standard'|'fine'|null`。
- `web/app.js`：首頁載入時 `GET /settings` 填表；按預設按鈕只改表單；按儲存 `POST /settings`，成功後更新 summary。
- 設定只影響之後的產課；正在跑的 job 不受影響（UI 一行註明）。

**extension**：不用改。疊層與圖示流程走同一個 server queue，自動吃到設定。

**文件**：README「開始用」或「費用」加一段「設定」：三個預設、各自速度／費用、`data/settings.json` 的位置、環境變數仍可覆寫（env 優先序：settings 檔 > env？→ 決定：settings 檔有值就用檔案，沒有才看 env；`YTLEARN_PROVIDER` 不在設定頁，維持 env）。

## 補充：擴充功能圖示的右鍵選單（使用者追加）

使用者右鍵點工具列圖示時，希望有「開首頁」與「設定」兩個入口。做法：

- `manifest.json` 加 `contextMenus` 權限。`background.js` 在 `chrome.runtime.onInstalled` 建兩個選單項（`contexts: ['action']`，id 固定、先 `removeAll` 再建避免重複）：「打開 yt-learn 首頁」→ `chrome.tabs.create({url: SERVER + '/index.html'})`；「設定」→ `chrome.tabs.create({url: SERVER + '/index.html#settings'})`。
- 首頁 `web/app.js` 載入時若 `location.hash === '#settings'`，把設定區 `<details>` 打開並捲到它；設定區的 summary 本來就會顯示目前摘要。
- 不用 `options_ui`（Chrome 的「選項」入口只能指向擴充功能自己的頁面，設定卻存在本機 server，繞一層沒有意義）。
- 測試：`tests/web/extension-overlay-messages.test.js` 的 fake chrome 加 `contextMenus.{removeAll,create,onClicked}`，斷言安裝時建了兩個項目、點擊各自開對的網址。

## Codex 審查後的裁定（覆蓋上面不一致處）

1. **effort = default 要清掉繼承的 env**：`BuildQueue._run` 組 env 時，saved effort 為 `default` 就 `env.pop("YTLEARN_EFFORT", None)`；`build.py` 把 `--effort default` 正規化成 `None`。
2. **模型與 effort 的設定只對 Claude 生效**：provider 是 codex 時 `build.py` 忽略 `YTLEARN_MODEL`（Codex 的模型仍照它自己的 config）；effort 對 Codex 以 `-c model_reasoning_effort="<low|medium|high>"` 傳（xhigh／max 降為 high，記錄實際生效值）。`CodexCliProvider.__init__` 要接 `effort` 並轉給父類別；`build.py:179` 兩個 factory 分支都要帶 effort。UI 註明「模型只對 Claude 有效」。`workers` 兩種 provider 都適用。
3. **快取鍵**：effort 為 None 時 hash 與現在完全相同（既有快取照常命中）；有明確 effort 時 hash 加入 effort。快取記錄多存 `effort`（缺就視為 default），讀取時 model 與 effort 都要相同。
4. **設定檔讀寫**：新模組 `pipeline/settings.py`：`DEFAULTS`、`VALID`、`normalize(obj) -> (settings, errors)`、`load(root) -> settings`（檔案缺／壞 → DEFAULTS，壞檔回傳附 `warning`）、`save(root, settings)`（同目錄唯一 tmp 檔 + `os.replace`，失敗清 tmp，仿 `server.py:179`）、`resolve(saved, env) -> effective`（優先序：saved > env > DEFAULTS；明確 CLI 參數高於一切，`YTLEARN_BUILD_CMD` 自訂指令不碰）。`GET /settings` 回 `resolve` 後的有效值（UI 顯示的就是會生效的）。
5. **讀取時機**：`_run` 在 `set_building` 之前讀一次完整快照，之後的 POST 不影響這次 build；同時 POST 以最後寫入為準。佇列中尚未開始的 job 會用開始當下的設定；UI 文案改成「設定套用在之後開始的產課」。
6. **壞掉的 settings.json**：build 不失敗，改用預設值並在 job log 第一行印 warning；GET /settings 也帶 `warning` 欄位給 UI 顯示。
7. **首頁路由**：設定區只在真正的首頁（網址沒有 `?v=`）顯示；`initHome(false)` 的「找不到課程」頁不顯示。
8. **其他**：`.gitignore` 加 `data/settings.json`；`build.py` 開始時印一行 `settings: provider=… model=… effort=… workers=…`；預設組合的說明改成定性（快／標準／細緻，不寫倍數）。
9. **測試補**：繼承 env 的 effort 被 default 清掉、saved 蓋過 env、CLI 蓋過 env、codex 不吃 model；settings 檔第一次寫入、壞檔讀取回預設、同時寫入；快取：default 命中舊紀錄、明確 effort 不命中舊紀錄、low→high→low 重用 low 的紀錄；POST 非物件、布林／小數 workers、非法 effort 都 400 且不寫檔。
