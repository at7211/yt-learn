# yt-learn：Netflix 播放頁的雙語字幕疊層（第三個站點；選擇性開啟的唯讀鉤子）

第 5 版，2026-10-31（第 1–3 版各被 Codex gpt-6-astra 退回 17、12、7 條；第 4 輪 Codex 額度用盡，改由新上下文的 Opus 審查員審 7 條的關閉情形，「修改後核准」6 條 F1–F6；四輪裁決在文末）。前兩個站點的計畫：`2026-10-29-youtube-overlay.md`、`2026-10-31-udemy.md`（Udemy 已在 main feff80d，extension 1.5.0）。

## 背景與已驗證事實（2026-10-31，在使用者登入的 Chrome 上實測《薪酸打工仔》S1E1/E2）

- 播放頁 `https://www.netflix.com/watch/<movieId>[?trackId=…]`，SPA；從 `/browse` 點播放、按「下一集」都只換路徑（pushState），不建立新 document；`<video>` 沿用或重建未確認（引擎已用 {root, video} 身分比對，兩種都處理）。
- DOM：`video` → … → `[data-uia="video-canvas"]` → `[data-uia="player"]` → `.watch-video--player-view`（position:absolute，佔滿視窗）→ `.watch-video`（**全螢幕元素，按 F 驗證**）。原生字幕畫在 `.player-timedtext`；`video.textTracks` 為空。
- 沒有強制 CSP、沒有 Trusted Types（report-only 而已）。
- 字幕清單只存在 manifest 裡：頁面每換一部片就經 MSL（加密）向 `/msl/playapi/cadmium/licensedmanifest/1` 要一次，解密後交給 `JSON.parse`；擴充無法重發這個請求。所有現成擴充（Subadub、NflxMultiSubs、easysubs、Language Reactor）都在 MAIN world、document_start 包 `JSON.parse`，認 `result.movieId` + `result.textTracks`（2026-07 由 `timedtexttracks`/`ttDownloadables` 改名為 `textTracks`/`downloadables`；舊版網址在 `downloadUrls{}`，新版在 `urls[].url`）。
- **不改請求**時 manifest 就有的文字格式：英文 PRIMARY 與 ASSISTIVE（SDH）各有 `imsc1.1`、`dfxp-ls-sdh`、`simplesdh`；繁中有 `imsc1.1`、`nflx-cmisc`。網址是簽名的 `https://ipv4-c0NN-<pop>-<isp>.1.oca.nflxvideo.net/?o=…`，從頁面用 `fetch(url, {credentials:'omit'})` 跨域可讀（CORS 放行；isolated world 未驗，列入 gate A）。
- `imsc1.1` 檔：`text/xml`，`<tt ttp:contentProfiles="http://www.w3.org/ns/ttml/profile/imsc1.1/text" xmlns="http://www.w3.org/ns/ttml" … ttp:tickRate="10000000" ttp:timeBase="media">`，`body > div > p`，一句一個 `<p xml:id="subtitleN" begin="127916667t" end="145416667t" region="region0"><span style="style1">Mm. Slow night.</span></p>`，多行用 `<br/>`，SDH 式音效標記如 `-[door opens]` 也出現在 PRIMARY 軌；20 分鐘一集約 340–390 句；無圖片字幕。
- 頁面播放器 API（MAIN world）：`netflix.appContext.state.playerApp.getAPI().videoPlayer`，`getAllPlayerSessionIds()`（watch 頁的 id 以 `watch-` 開頭），`getVideoPlayerBySessionId(id)` → `getCurrentTime()`（ms）、`getDuration()`、`getMovieId()`、`getTimedTextTrackList()`、`setTimedTextTrack(t)`、`seek(ms)`、`play()`/`pause()`。**直接設 `video.currentTime` 會觸發 M7375**，讀是安全的；`video.pause()` 實測安全，`video.play()` 未驗（gate A）。
- 控制列（`[data-uia="control-next"]` 等）只在真實滑鼠移動時才存在於 DOM；合成 mousemove 叫不出來。同一帳號第二個分頁播同一部片會得到 M7020。
- Chromium 在派送 contextMenus.onClicked 時帶 user gesture（`menu_manager.cc`），`permissions.request` 可以直接在 listener 裡呼叫；`registerContentScripts` 的 `world:'MAIN'` 自 Chrome 102 可用（manifest 最低 120）；註冊不會回溯到已載入的頁面；MV3 service worker 隨時可能被終止，`onStartup` 只在 profile 啟動時觸發一次，不是每次甦醒。
- 使用條款 §1.8：(ii) 禁止複製／衍生內容、(vi) 禁止插入任何程式碼、(vii) 禁止資料擷取。沒有找到對字幕擴充執法的公開紀錄；Netflix 的反制是改欄位名（2019、2020、2022、2026）。

## 設計決定

1. **預設全關；持久化的是使用者意圖，worker 每次醒來都把現實對齊到意圖。**
   - `chrome.storage.local.netflix = {desired: boolean, gen: integer, cleanup: boolean}`。`gen` 在每次使用者切換時 +1；每個非同步操作（啟用、關閉、擷取、ingest）開始時記下 `gen`，每個 await 之後核對，不同就放棄。`cleanup=true` 表示「關閉的清理還沒做完」。
   - **`reconcileNetflix()`**：worker 檔案頂層就呼叫（每次 worker 建立都跑，不靠 `onStartup`），也在 `onInstalled`、`permissions.onRemoved`、每次 Netflix 相關入口前跑。**不監聽 `permissions.onAdded`**（啟用流程自己會送 set；監聽它會和啟用競爭）。所有**狀態變更**經同一條 promise 串列化，寫法沿用 `background.js` 的 `dictQueue`：`const run = q.then(fn); q = run.catch(() => {}); return run`（佇列尾端吸收 rejection、呼叫者仍收到錯誤）。分成 `reconcileInner()`（不排隊，純邏輯）與排隊的 `reconcileNetflix()`；set、disable 與入口檢查都是**一個**排隊任務，任務內只呼叫 inner 版本（避免自己等自己）。**擷取與 ingest 不進這條佇列**（它們只在開始與 await 後讀 `gen`），否則關閉會被長擷取卡住。邏輯：讀 `{desired, cleanup}`；查 `permissions.contains(ORIGIN)`；查 `getRegisteredContentScripts({ids:[HOOK_ID, OVERLAY_ID]})` 並**比對完整設定**（js、matches、runAt、world、allFrames、persistAcrossSessions），不符就註銷重註冊。分支：`desired && 有權限` → 確保兩支都註冊（註冊失敗 → `desired` **保留**、記 log，下次 reconcile 重試；入口檢查因「未註冊」而拒絕，啟用頁顯示「註冊失敗，稍後會自動重試」）；`desired && 無權限`（使用者從 chrome://extensions 收回）→ 寫 `desired=false, gen+1, cleanup=true`，接著走下面的 `!desired` 分支；`!desired` → 若 `cleanup` 為 true 先重做 `site-off` 廣播（見關閉順序），再確保註銷，成功後 `cleanup=false`；**`!desired` 分支永不呼叫 `permissions.remove`**（只有使用者明確關閉才撤權；留著的權限無害，因為 worker 照樣拒絕）。這樣「授權成功 → set true」之間不論 worker 醒幾次都不會把剛拿到的權限撤掉。任何中途終止留下的半狀態，下次 reconcile 都收斂到 `desired`。
   - **啟用入口**：關閉狀態下在 `https://www.netflix.com/watch/<id>` 按圖示 → worker 開擴充自己的頁 `extension/netflix-enable.html`（說明鉤子做什麼、不做什麼、需重新載入播放頁；`?tab=<id>`），按鈕 handler 裡**直接** `chrome.permissions.request({origins:[ORIGIN]})`（擴充頁有 `chrome.permissions`），成功 → 送 `ytlearn:netflix-set {desired:true}` 給 worker → worker 在佇列任務裡**先查 `permissions.contains`**：沒有（例如前一個關閉任務剛撤掉）→ 什麼都不寫、回 `{ok:false, error:'needPermission'}`，啟用頁重新顯示授權按鈕；有 → 寫 `desired=true, gen+1, cleanup=false` → `reconcileInner`（註冊）→ 成功才 `tabs.reload(tab)` → 回 ok → 頁面自關；註冊失敗 → 回錯誤（`desired` 仍 true，下次 reconcile 重試）。拒絕授權 → 什麼都不寫、頁面顯示原因。右鍵 checkbox「在 Netflix 啟用」保留為進階入口：onClicked 裡**直接** `permissions.request`（勾選）或送 `desired:false`（取消），之後走同一條路。
   - **關閉的順序**（`disableNetflix`，可重入）：(1) 寫 `desired=false, gen+1, cleanup=true`；(2) 廣播 `{type:'ytlearn:site-off', site:'netflix'}`：有站點權限時 `tabs.query({url:'https://www.netflix.com/*'})`，沒有（外部撤權）時 `tabs.query({})` 對**所有**分頁 id 送、沒有接收端的錯誤忽略（overlay 只在自己的 `site.name === 'netflix'` 時處理，YouTube／Udemy 分頁收到不受影響）；單一分頁失敗不影響其它；(3) 註銷兩支腳本；(4) 寫 `cleanup=false`；(5) **再讀一次 storage，`gen` 仍等於本任務開始時的值**才 `permissions.remove`（失敗只記 log）；`gen` 變了表示使用者已再次啟用，權限保留。worker 在任一步之後被殺，下次 reconcile 看到 `cleanup=true` 就從 (2) 重做。外部撤權（`permissions.onRemoved`）走 reconcile 的 `desired && 無權限` 分支，等於同一條路少了 (5)。
   - **關閉狀態下 worker 一律拒絕 Netflix**：`onIconClicked`、`ytlearn:build`、`runJobInner` 三個 build 入口在 `/add` 之前先 `await reconcileNetflix()` 再檢查「`desired && 有權限 && 已註冊`」，否則走啟用頁（圖示）或回錯誤「Netflix 尚未啟用」（訊息入口）；worker 端兩處檢查：`overlayFetch`（處理 `ytlearn:lesson`、`ytlearn:job`）與 `runJob` 的 build 分支（`ytlearn:build`）對 netflix id 在關閉狀態一律回 `{disabled:true}`；`ytlearn:netflix-probe` 的 `{disabled:true}` 由啟用頁自己處理；`ytlearn:dict` 不檢查。overlay 端在 `send()` 一處攔截（設計 9）。**ingest 的提交界線**：關閉只保證「還沒送出 `/ingest` 的擷取不會送出」（送出前核對 `gen`，過期就 `/fail`）；已送出的 ingest 照常完成（結果是本機一個 lesson 檔，無害），驗收文字照此寫。Netflix 與 Udemy 一樣沒有背景模式。
2. **鉤子只讀不改，對 `JSON.parse` 透明，關閉後永久 no-op。** `netflix-hook.js`（MAIN world、document_start，與 `netflix-manifest.js` 同一次註冊）：
   - 重入防護：`globalThis.__ytlearnNfHook` 已存在就不再安裝。wrapper 用 `Reflect.apply(orig, this, arguments)` 呼叫**一次**，原生例外原樣丟出；只有摘要工作在 try/catch 裡，回傳同一個結果物件，不修改、不 stringify、不重 parse。帶 reviver 的呼叫不摘要（計數器 `stats.skippedReviver`，gate A 驗證 Netflix 的 manifest 解析不帶 reviver）。
   - **兩層偵測**：「疑似 manifest」= 根物件或 `.result` 之下有正整數 `movieId` 且有 `textTracks`/`timedtexttracks`/`audioTracks`/`audio_tracks` 任一鍵（型別不拘）；疑似者交給 `ytLearnNetflixSummarize`，成功 → 存摘要，失敗 → 以 movieId 記 `unknownShape[movieId] = true`。計數器 `stats = {parsed, suspected, summarized, unknownShape, skippedReviver}`。
   - 摘要：`{movieId: String, durationMs, tracks:[{lang, type, name, forced, formats:{fmt: url}}]}`，`lang = bcp47|language`、`type = trackType|type`、`name = displayName|languageDescription`（≤ 128 字）、`formats` 只收固定鍵 `imsc1.1`、`dfxp-ls-sdh`（其餘丟棄），每鍵取第一個 `https:` 網址（`urls[].url` 或 `downloadUrls{}` 的值）。以 movieId 為鍵，同 id 覆寫（新簽名取代舊簽名），最多留 10 筆（LRU）。不改送出的請求、不發請求、不寫 console。
   - 收到 `ytlearn:nf-off`：`disabled=true`（之後 wrapper 只呼叫原函式、不摘要；所有命令回 `{ok:false, error:'off'}`）、清空快取；若 `JSON.parse === 自己的 wrapper` 則還原原函式，否則留著但已 no-op。
3. **兩個 world 之間用 `window.postMessage`，橋接資料一律當不可信。**
   - **契約按訊息 type 分開定義，兩端共用 `netflix-manifest.js` 裡的同一份 validator 與測試**：
     - `nf-get` 請求 `{type, nonce, movieId}` → 回覆 `{type:'ytlearn:nf-manifest', nonce, hook: HOOK_VERSION, movieId: 問的那個, state, manifest?, title?, show?, currentMs?, stats}`（`currentMs` = 該 movieId 的播放器 `getCurrentTime()`，找不到 session 就省略；probe 用它當 seek 目標）；
     - `nf-seek` 請求 `{type, requestId, expectedMovieId, ms, play}` → 回覆 `{type:'ytlearn:nf-seek-ack', requestId, hook, ok, error?}`（ack **一律帶 `hook`**）；
     - `nf-off` 無回覆；關閉後任何請求的回覆都是該 type 對應的回覆形狀、`state:'off'`（get）或 `ok:false, error:'off'`（seek）。
     - validator 三個，都在 `netflix-manifest.js`：`ytLearnNfValidateRequest(msg)`（鉤子端）、`ytLearnNfValidateGetReply(msg, askedMovieId)`、`ytLearnNfValidateSeekAck(msg, requestId)`（呼叫端）；沒有 `nf-probe-seek` 這種 type，probe 走一般 `nf-seek`。
     `nf-get` 的 `state ∈ {'found','pending','unsupported','off'}`：`found` 必帶 `manifest`（其 `movieId` 須等於問的）、可帶 `title/show`；`pending` = 鉤子在、這個 movieId 既沒有摘要也沒有 unknownShape 紀錄，**禁止**帶 manifest；`unsupported` = 這個 movieId 有 unknownShape 紀錄（別部片的 unknownShape 不影響）；`off` = 已關閉。擷取方對 `pending` 在總 deadline 內每 500 ms 重問；最終失敗訊息分開：「Netflix 鉤子不在（請重新載入頁面）」（沒有任何回覆）、「還沒收到這部片的字幕清單」（一直 pending）、「Netflix 改版了，認不出字幕清單」（unsupported）。
   - seek：overlay → 鉤子 `{type:'ytlearn:nf-seek', requestId, expectedMovieId, ms, play}`，`ms` 有限非負整數、`play` 嚴格 boolean；鉤子取 `watch-` 開頭且 `String(getMovieId()) === expectedMovieId` 的 session，再核對網址的 movieId，`getDuration()` 有限正數且 `ms ≤ duration`，全對才 `seek(ms)`，`play` 為 true 再 `play()`；回 `{type:'ytlearn:nf-seek-ack', requestId, ok, error?}`，**ack 的語意是「API 已呼叫」**，不是「已到位」。
   - 兩邊都先掛 listener 再 post、都檢查 `event.source === window && event.origin === 'https://www.netflix.com'`、`targetOrigin` 一律 `'https://www.netflix.com'`、訊息只含 JSON 可表示的值；完成、逾時、換集、關閉時移除 listener 與計時器。擷取方驗證回覆：版本、state 的必要／禁止欄位、`manifest.movieId`、tracks ≤ 200、每軌 formats 只有允許鍵、字串 ≤ 256（url ≤ 2048）、整則訊息序列化 ≤ 64 KB；每個 url 為 `https:`、無 userinfo、無 port、hostname 以 `.nflxvideo.net` 結尾；fetch 用 `redirect:'error'`，回應讀成 `arrayBuffer` 後長度 ≤ 2 MB 才解碼。同源檢查只排除其它 window，不當作對 MAIN world 的認證；nonce 只配對。
4. **字幕軌選擇與格式。** 候選 = 非 forced、`lang` 符合 `/^en([_-]|$)/i`、`formats` 非空的軌；排名 PRIMARY > ASSISTIVE，同級內 `en`/`en-US` 優先；沒有候選 → 「這部片沒有英文字幕」。格式 `imsc1.1` → `dfxp-ls-sdh`。繁中：`lang` 符合 `/^zh-Hant/i` 的非 forced 軌，同樣規則，**選用**：抓不到、解析失敗、**或解析成功但不符合 ref 的 schema 上限（≤ 5000 筆、總字元 ≤ 200k、`d>0`、`t` 遞增）**——capture 組 raw 前用與 server 相同的規則自檢，不合格就整個拿掉 `ref`——都只是 `refStatus: 'missing'|'failed'`，英文照常 ingest（schema 選用字串欄位，lesson 不帶）；**能見度 = worker log 一行 `capture:ref <status>`**，不改 pill、不改 job 欄位。英文軌的任何失敗（HTTP、abort、非 TTML、空內容、`duration` 非有限正數、超過一半的 cue 超出片長）都是錯誤，沿用 Udemy 的 AbortController、總 deadline 25 s、`duration` 先 `manifest.durationMs/1000` 再 `video.duration`（loadedmetadata ≤ 5 s）。
5. **TTML 解析器 `extension/ttml.js`：封閉子集，不支援就拒絕，不猜。** `globalThis.ytLearnParseTtml(text) → {events, dropped}`，與 vtt.js 同形狀。不依賴 DOMParser（node 測試沒有；擴充不能帶套件），自寫**嚴格**的 tokenizer，只認下列結構，其它一律丟 `Error('不支援的字幕檔結構：…')`：
   - 文件：可選 BOM、可選 `<?xml …?>`、**禁止** `<!DOCTYPE`／實體宣告；單一根元素，本地名 `tt`（允許任意前綴），`xmlns` 或前綴對應的 namespace URI 必須是 `http://www.w3.org/ns/ttml` 或 `http://www.w3.org/2006/10/ttaf1`；參數屬性以 **namespace URI** `http://www.w3.org/ns/ttml#parameter`（或 2006 的 `…/ttaf1#parameter`）辨認，不是字面 `ttp:`。標籤必須成對、屬性值必須加引號、實體只接受 `&amp; &lt; &gt; &quot; &apos; &#N; &#xN;`；節點數 ≤ 50,000、深度 ≤ 16、cue 數 ≤ 10,000、輸入 ≤ 2 MB。
   - 允許的元素：`tt > head?（整個略過，但仍需結構正確）, body > div* > p*`；`p` 內只允許文字、`span`（任意屬性、可巢狀）、`br`。`body`、`div`、`span` 上出現 `begin/end/dur/timeContainer` 任一 → 拒絕；`p` 必須有 `begin` 與（`end` 或 `dur`），兩者都有時 `end` 優先且 `dur` 必須一致（±1 ms）否則拒絕；`p` 上 `timeContainer` → 拒絕；`p` 內其它元素（`metadata`、`image`、ruby 等）→ 拒絕。
   - 時間參數：`timeBase` 缺省或 `media` 接受，其它拒絕；`frameRate` 缺省 30、`subFrameRate` 缺省 1、`frameRateMultiplier` 缺省 `1 1`；**所有數值先驗證再換算**：`frameRate`、`subFrameRate`、`tickRate`、multiplier 的分子與分母都必須是正整數（0、負數、非數字、非整數一律拒絕）；**有效 frameRate = frameRate × 分子 / 分母**；`tickRate` 缺省 = 有效 frameRate × subFrameRate（有 `frameRate` 屬性時才用這條，否則 1）。正例：`frameRate=30 multiplier="1000 1001" subFrameRate=1` 無 tickRate 時，`30000t` = 1001 s。時間表達式：`hh:mm:ss(.fff)`、`hh:mm:ss:ff(.sub)`（用有效 frameRate、subFrameRate）、offset `N(.N)?(h|m|s|ms|f|t)`；其它拒絕。
   - 內文：`br` → 空白、剝 `span` 標籤保留文字、解實體、合併空白；清理：刪 `[...]` 整段（SDH 標記）、刪 `♪` 符號（歌詞文字保留）、整句只剩 `(...)` 的丟掉（**句中的括號文字保留**）、刪清理後殘留的行首 `-`、修剪；空的丟掉。
   - 時間正規化（毫秒整數後做）：同 `begin` 的多個 cue 合成一句（文字依文件順序、`end` 取最大）；穩定排序；`end<=begin` 丟；`d` 截到下一句 `begin`；**截完後 `d` 小於「該句 token 數 × 2 ms」的句子併入下一句**：token 數 = 以空白切分的數量（與 `words.py:_tokens` 的計數相同或更多）；併後 `begin` 用短句的、`end` 用下一句的、文字前置；可以連鎖（併完仍太短就再併）；最後一句太短就併入前一句（`end` 取大）。這讓 `normalize_words` 的每個窗口都至少有 token 數 × 2 ms；最後斷言 `t` 嚴格遞增（違反就合併）。
6. **繁中官方字幕給 LLM 當有時間座標的參考，不寫對齊程式；沒有參考時提示逐字不變。**
   - raw 選用欄位 `ref: {lang:'zh-Hant', kind:'official', events:[{t, d, text}]}`，schema 驗：`t`/`d` 為非 bool 整數、`d>0`、`t` 遞增、`text` 非空字串、≤ 5000 筆、總字元 ≤ 200k；只允許和 `events` 同時出現。
   - **時間資料**：`normalize_words` 的每個 word 多一個鍵 `ev`（來源 event 的索引；既有測試用 `==` 比對整個 dict 的要改成子集比對或補鍵）。**同時修 `pipeline/words.py:_spread_untimed` 的既有 bug**：為了讓相鄰字嚴格遞增而做的 `+0.001` 推進沒有被窗口終點擋住，一個 1 ms 長、四個字的 event 會把第四個字推到下一個 event 之後（Codex 第 3 輪用現有程式重現：起點 `0, .001, .002, .003, .001`）。修法（整數毫秒分配）：`s_k = max(比例值, s_{k-1} + 1)`，同時 `s_k ≤ window_end − (n − k)` ms（從後往前的上限）；只要 `span_ms ≥ n` 結果必定嚴格遞增且 `< window_end`（TTML 的 2 ms/token 併句規則保證這個條件）；只有 `span_ms < n`（YouTube 等來源的極端情況）才退回「其餘字落在 `window_end`、允許相等、不允許倒序」。測試：1 ms 四字 event 不倒序、不跨越下一個 event；8 ms 窗口放 `internationalization a b c` 仍嚴格遞增；TTML 路徑斷言嚴格遞增。這是獨立於 Netflix 的修正，放在步驟 3。`segment_user_prompt(words, a, b, *, ref=None)`：有 ref 時，在 chunk 第一個字之前、以及每次 `words[i].ev` 變動時插入一行 `@mm:ss.d`（用 `words[i].t`）；chunk 的時間範圍 `[words[a].t, words[b].e)`（秒）；ref 的 `t/d` 先 ÷1000 轉秒，與範圍**半開區間重疊**的參考句附在末尾區塊「官方繁中字幕（參考）」，格式 `mm:ss.d–mm:ss.d 文字`。system prompt 用 `SEGMENT_SYSTEM + SEGMENT_REF_ADDENDUM`：「**英文語意優先**；時間重疊的參考句供用詞參考，語意相符就沿用，不符就自己翻；不得把英文沒說的內容寫進 zh。」`make_cues(words, chunk, provider, stats=None, *, ref=None)`。沒有 ref：`SEGMENT_SYSTEM`、user prompt、`SEGMENT_SCHEMA` 三者 byte-for-byte 不變（golden 測試斷言 provider 收到的三個參數），快取照常命中。測試：chunk 從來源 cue 中間開始、時間間隙、毫秒換算、一對多、多對一、跨 chunk 邊界、參考缺段。
   - 已 done 的 job 不會因為多了 ref 自動重建；要套用就刪 lesson 重跑（README 一句）。
