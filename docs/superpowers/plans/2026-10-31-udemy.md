# yt-learn：Udemy 講座頁的雙語字幕疊層（第二個站點轉接層）

第 2 版（2026-10-31）：併入 Codex gpt-6-astra 審查的 12 條與 Spike 結果。第 1 版的差異列在文末。

## 背景與已驗證事實（2026-10-31，在使用者登入的 Chrome 上實測）

- 講座頁網址 `https://www.udemy.com/course/<slug>/learn/lecture/<lectureId>`（後面可能帶 `?start=0#overview`）。換課是 SPA：`window` 上的標記換課後仍在。
- 播放器是 Shaka。DOM：`<video id="lecture-<assetId>">` → `div#shaka-video-container-<assetId>` → `div[data-purpose="shaka-video-player"]`（**`position: relative`**，與 `<video>` 同尺寸 1504×673）→ `div.video-viewer--container--…` → `section.lecture-view--container--…` → `div[data-purpose="curriculum-item-viewer-content"]`。
- **換課時 `<video>` 整個換新**：舊元素從 DOM 移除（`document.contains(old) === false`），新元素 id 隨 assetId 變，仍在同一個 `shaka-video-player` 選擇器下；外層 root 本身是否被重建未能確認（兩種都要處理）。
- 字幕不是 `<track>`（textTracks 只有一條 hidden、0 cues），Udemy 自己把 cue 畫在 `div._caption-container_<hash>` > `div._cue-text_<hash>`。
- `courseId` 可從 `div.ud-app-loader[data-module-id="course-taking"]` 的 `data-module-args` JSON 直接讀（實測 `{courseId: 775330, initialCurriculumItemId, …}`），伺服器端渲染、頁面一載入就在。
- 頁面自己會打 `GET /api-2.0/users/me/subscribed-courses/<courseId>/lectures/<lectureId>/`（same-origin，帶 cookie）。加 `?fields[lecture]=title,asset&fields[asset]=captions,length,title` 後回傳 `title`、`asset.length`（秒）、`asset.captions[] = {locale_id:"en_US"|"tr_TR"|…, source:"auto"|…, url}`（實測從頁面 context 呼叫成功）。
- 字幕檔：`https://vtt-c.udemycdn.com/<assetId>/<locale>/<file>.vtt?Expires&Signature&Key-Pair-Id`（預覽播放器是 `vtt-cf.`）。WebVTT、整句時間、無逐字時間、`<v Narrator>` 標籤、CRLF。頁面用 fetch 抓它（CORS 已開），從頁面 context 再 fetch 一次成功（87 cues / 3:35）。
- 有的課程是 DRM（CMAF cbcs + `media-license-server`），不影響 `currentTime` 與字幕。
- 自動字幕有 36 種語言，中文只有簡中；英文常見是 `source:"auto"`。使用者在那堂課上次選的是土耳其文，所以**不能靠「目前顯示的字幕」**，要自己挑英文那條。
- 控制列按鈕：`[data-purpose="fullscreen-toggle"]`、`[data-purpose="theatre-mode-toggle-button"]`。
- 課程預覽彈窗（未購買）用同一套播放器（`div._media-player_…`），v1 不支援預覽彈窗。
- 管線 `pipeline/words.py:normalize_words` 本來就接受無逐字時間的字幕（依字數攤平），管線不用改。
- **未驗證**：全螢幕時 `document.fullscreenElement` 是哪一層。自動化按 F、雙擊、點 `fullscreen-toggle` 都沒有觸發 `fullscreenchange`（疑似自動化輸入不算使用者啟動）。設計上掛在 `shaka-video-player`（Shaka 慣例是對 video container 或其祖先 requestFullscreen），**由使用者在第 6 步實測時按 F 驗**；若疊層消失，備案是改掛 `curriculum-item-viewer-content`。
- **未驗證**：isolated world 的 content script 對 API / 簽名 VTT 的 fetch。Chrome 的 content script 受頁面同源與 CORS 規則約束（host permission 不繞過），而兩個請求在頁面 context 都成功，預期一致；第 3 步完成後先在真實擴充裡跑一次再往下。
- Udemy 條款頁回 403 沒讀到原文。設計上只重現頁面自己已經做的兩個請求（一次講座 API、一次 VTT），由使用者按圖示觸發，不批次、不背景。

## 耦合地圖（Explore 代理整理，file:line）

全系統唯一真正的阻礙是 **id 必須是 11 碼**：
`pipeline/jobs.py:21 ID_RE`、`pipeline/schema.py:4 VIDEO_ID_RE`（validate_raw :22、validate_lesson :72）、`pipeline/build.py:16,160`、`web/ytid.js:3`、`extension/ytid.js:3`、`extension/overlay-state.js:4,14 watchVideoId`、`extension/overlay.js:73` 後備 regex。
路徑型路由（`/jobs/<id>`、`/jobs/<id>/claim|fail`、`/data/lessons/<id>.json`）不驗 id；檔名用 id（raw/lessons/cache/jobs）。
YouTube URL 只在：`jobs.py:26 canonical_url`、`extension/ytid.js:22`（background.js:302,305 送 /add）、`web/ytid.js:24`、`web/app.js:200 postAdd`、`web/app.js:564 initPlayer` 的 YouTube iframe、`background.js:169,387`、`server.py:41-59`（Origin 白名單，worker 的 fetch 帶 `chrome-extension://` Origin，**伺服器不用加 udemy Origin**）。
`/lessons`（`server.py:145-150`）以固定欄位重建列表，沒有 source 欄位。
`validate_raw` 要 `videoId,title,channel,duration,lang,kind,events`；`kind` 任意非空字串、下游沒人讀；`channel` 進 intro prompt 當「頻道」並顯示在列表。lesson JSON 沒有 url 欄位。
`web/ytid.js` 是 ESM、`extension/ytid.js` 是 `importScripts` 用的全域腳本，兩者不是逐位元複本。

## 設計決定

1. **id 格式（Codex #1）**：YouTube 維持 11 碼；Udemy 用 **`udemy.<lectureId>`**（點號不在 YouTube id 字元集 `[A-Za-z0-9_-]` 內，任何長度都不會碰撞；檔名安全）。全系統的 id regex 統一為 `^(?:[A-Za-z0-9_-]{11}|udemy\.[0-9]{1,12})$`，只放一處：Python `pipeline/ids.py`（`LESSON_ID_RE`、`parse_lesson_id(url_or_id)`、`source_of(id) → "youtube"|"udemy"`、`parse_udemy_url(url) → (slug, lectureId)|None`），JS `web/ytid.js`（ESM）與 `extension/ytid.js`（全域）各自新增 `parseLessonId`、`lessonSource`、`parseUdemyUrl`，**`parseVideoId` 的接受／拒絕契約不變**（既有 `urls.json` 測試照跑），新增 fixture `tests/fixtures/lesson_ids.json` 給三端共用。
2. **raw 與 lesson 多兩個欄位**：`source: "youtube"|"udemy"`（缺省視為 youtube）、`sourceUrl`。`validate_raw`/`validate_lesson`：`source` 若有必須與 id 的 `source_of` 一致，否則拒絕；`sourceUrl` 若有必須是 `https://www.udemy.com/course/<slug>/learn/lecture/<id>` 且 `<id>` 與 videoId 一致（Codex #11：手動匯入的 JSON 會原樣進伺服器，這是新的外部連結入口），否則拒絕。`build.py` 原樣帶進 lesson。
3. **/add 接受 Udemy 網址**：`server.py:219` 改用 `parse_lesson_id`；錯誤訊息「無法辨識的 YouTube 或 Udemy 網址」。`canonical_url` 對 udemy id 回 None。**`/lessons` 回傳加 `source`、`sourceUrl`**（Codex #2）。
4. **worker 的 id 一致性契約（Codex #3）**：圖示點下時凍結 `requested = {id: parseLessonId(tab.url), url: tab.url}`；`/add` 送 `{url: requested.url}`，回來的 id 必須等於 `requested.id`，否則中止；擷取腳本收 `expectLessonId`，起點與回傳前都核對網址（同 `capture.js:48` 的 checkNav）；worker 在 `/ingest` 前驗 `raw.videoId === requested.id`，不符則 `/jobs/<id>/fail` 並報錯「換課了，請回到原講座再試」。YouTube 路徑同樣套這條（原本只有 capture 內核對）。
5. **擷取走講座 API（Codex #6、#7、#8）**：新檔 `extension/udemy-capture.js`（isolated world；worker 的 `injectCapture` 兩階段都要依站點選 world，`background.js:401-409`）：
   - lectureId 從網址；courseId 從 `.ud-app-loader[data-module-args]`（JSON 解析失敗或沒有 → 等 Resource Timing 出現精確符合 `/subscribed-courses/(\d+)/lectures/<lectureId>/` 的紀錄，最多 `timeoutMs`，**不清空頁面的資源紀錄**；仍沒有 → 錯誤「找不到課程 id」）。
   - `GET /api-2.0/users/me/subscribed-courses/<courseId>/lectures/<lectureId>/?fields[lecture]=title,asset&fields[asset]=captions,length,title`，`credentials:'same-origin'`，AbortController 逾時；401/403 → 「請先登入 Udemy」；其他非 2xx → 帶狀態碼的錯誤；回應必須是 JSON 且有 `asset`。
   - 挑字幕：先過濾 `url` 是 `https:` 的項目；語系用 `/^en([_-]|$)/i` 精確匹配；優先 `source` 存在且 `!== "auto"`，其次 `en_US`，其次第一個 en；`source` 缺失視為未知（kind 記 `"unknown"`，不當人工）。沒有英文 → 「這堂課沒有英文字幕」。
   - fetch VTT：`credentials:'omit'`，逾時，非 2xx → 「字幕檔下載失敗（HTTP n）」，內容開頭不是 `WEBVTT`（允許 BOM）→ 「字幕檔格式不對」。
   - `duration`：`asset.length` 為有限正數才用；否則等當前 root 內那支 `<video>` 的 `loadedmetadata`（最多 5 s）取 `video.duration`；都沒有 → 明確失敗。
   - `channel` = 課名（`document.title` 去掉 `Course: ` 前綴與 ` | Udemy` 後綴，空則 `Udemy`）；`title` = 講座 title；`lang:"en"`；`kind`: `"asr"`（auto）/`"manual"`/`"unknown"`。
   - 回傳 `{videoId:"udemy.<lectureId>", source:"udemy", sourceUrl: location.origin+pathname, title, channel, duration, lang, kind, capturedAt, events}`。
6. **VTT 解析是純函式（Codex #9）**：新檔 `extension/vtt.js`，`globalThis.ytLearnParseVtt(text) → {events, dropped}`；`t`/`d` 都是**整數毫秒**。規格：去 BOM；CRLF/LF；略過 `WEBVTT` 標頭行與其後的標頭區、整個 `NOTE`/`STYLE`/`REGION` 區塊、非數字與數字的 cue 識別行；時間 `hh:mm:ss.mmm` 或 `mm:ss.mmm`，時間後的 cue settings 忽略；文字去 `<v …>`/`</v>`/`<c.foo>`/`<i>`/`<b>`/`<u>`/`<ruby>`/內嵌時間標籤 `<00:01.000>`，解 `&amp; &lt; &gt; &nbsp; &lrm; &rlm;`，多行以空白合一、壓縮空白；**每個 cue 一個 seg `[[null, text]]`**（整句交給管線分詞，保住 `[clears throat]` 之類聲音註記的既有移除邏輯）；空文字、`end <= start`、起點早於前一個「保留的」cue 的 cue 丟掉並計入 `dropped`；`d` 以下一個保留 cue 的 `t` 截短；沒有結尾空行也要吃。
7. **overlay.js 拆成引擎＋站點轉接層（Codex #4、#5）**：
   - 新檔 `extension/site.js`（ESM，overlay.js 動態 import；純函式部分可 vm 測）：`siteFor(hostname)` → `{name, lessonId(url, doc), findPlayer(doc) → {root, video}|null, isAd(root), nativeCaptionCss, navEvents: string[]}`。YouTube 轉接器保留現有行為：`lessonId` 在 `ytd-watch-flexy[video-id]` 與網址不一致時回 null、`findPlayer` 先 `video.html5-main-video` 後退 `video`；`isAd` 用 `O.adShowing`；`nativeCaptionCss` 是現有那條；`navEvents:['yt-navigate-finish']`。Udemy：`lessonId` 從網址 `parseLessonId`；`findPlayer` 找 `[data-purpose="shaka-video-player"]` 與其內第一個 `video`，少一個就 null；`isAd` 恆 false；`nativeCaptionCss` = `[data-purpose="shaka-video-player"].ytlearn-on [class*="caption-container"]{opacity:0}`；`navEvents:[]`。
   - `overlay.js` 引擎：所有 `#movie_player`、`ytd-watch-flexy`、`yt-navigate-finish`、`ad-showing` 的引用改走轉接器。**輪詢（1 s）同時比對 id 與 `{root, video}` 身分**：任一變了 → generation++ → teardown → mount（同 id 換 video 也重掛，Codex #4）。`playerReplaced` 事件進 `overlay-state.js` 的 `navigate`（新增 `token` 參數：同 id 但 token 不同也要重置 generation）。自動換課**只重新載入課程，不重新發起擷取**（建課只由圖示點擊觸發）。`ytlearn:toggle` 在動態 import 完成前先 `await ready`，不再回 `{handled:false}` 讓 worker 誤入後備流程（Codex #5）。
   - `overlay-state.js`：`watchVideoId` 改名 `lessonIdFromUrl`（YouTube 11 碼或 `udemy.<id>`），舊名保留為別名；狀態機仍不認識站點。
   - `overlay.css` 不變。root 若非 positioned（目前兩站都是），mount 時加 `style.position='relative'` 並在 teardown 還原。
8. **background.js**：`siteOfUrl(url)`（`www.youtube.com/watch` 或 `www.udemy.com/course/*/learn/lecture/*`）取代 `:169` 的字串判斷；兩站都走 `askOverlay` → 沒課程才 `runJob('inplace', requested)`；Udemy 不支援 background 模式（非講座頁按圖示 → 開首頁）；`ytlearn:lesson|job|build` 的 id 驗證改 `parseLessonId`；`build` 訊息也帶 `requested`。
9. **manifest.json**（1.5.0）：`host_permissions`、`content_scripts`（overlay.js）、`web_accessible_resources` 的 matches 加 `https://www.udemy.com/*`；resources 加 `site.js`、`vtt.js`。
10. **本機頁 `web/app.js`（Codex #10、#11）**：共同建課入口（`startJob`→`postAdd`）對 `lessonSource(id)==='udemy'` 直接拒絕，卡片文字「Udemy 課程請在講座頁按擴充圖示產生」，失敗卡片的「重試」同樣不出現；`?v=udemy.…` 有課程時不建 YouTube iframe，進 review 狀態顯示單字複習格，單字按鈕不呼叫 seek、改為無作用並提示「在 Udemy 頁面上播放」；`sourceUrl` 經 `parseUdemyUrl` 驗證（https、`www.udemy.com`、lecture 路徑、id 一致）才渲染成連結，否則只顯示文字。首頁列表對 udemy 課程顯示「Udemy」標籤並連到驗證過的 `sourceUrl`。
11. **伺服器**：`/add` 與 `/lessons` 如上；Origin 不加。
12. **v1 不做**：Coursera、課程預覽彈窗、未購買課程、Udemy Business 子網域、非英文字幕的課、逐字對時。

## 風險

- Udemy 的 class 名帶 hash，選擇器只用 `data-purpose` 與 `[class*=…]`；hash 改版會壞的是「隱藏原生字幕」，不影響疊層本身。
- 講座 API 欄位名是實測看到的，沒有官方文件；fixture 照實測樣本寫。
- 全螢幕掛載層級未驗，有備案。
- 條款：只重現頁面自己的兩個請求，個人本機使用；README 寫明。

## 第 1 版 → 第 2 版的差異

- id 由 `udemy-<id>` 改為 `udemy.<id>`（碰撞）。
- `/lessons` 要帶 `source/sourceUrl`；`sourceUrl` 與 `source` 要驗證。
- worker 增加 requested id 一致性契約。
- 引擎輪詢比對播放器身分，不只比 id；toggle 等 ready。
- courseId 改以 `ud-app-loader` 為主，Resource Timing 為備，不清空紀錄。
- fetch 的 credentials、逾時、狀態碼、格式檢查寫明；字幕挑選規則與 duration 後備寫明。
- VTT 輸出整句 seg、毫秒整數、邊界案例清單。
- 本機頁在共同建課入口拒絕 Udemy；review 狀態的 seek 處理。
- 測試順序改成先驗真實 fetch，再 id/伺服器，再 parser、adapter、本機頁、回歸。
